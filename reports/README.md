# Reports

Paper-facing results. The report calls no LLM; it is built from saved run outputs under `data/runs/`.

| File | What it is | How it is produced |
|---|---|---|
| [main-e1-e7-results.md](main-e1-e7-results.md) | Full results: setup, findings, main result, experiments E1–E7, independence checks, and a paper-changes checklist | Generated by `gurma report`. Do not edit by hand. |

## Which runs the report reads

All runs with an LLM guard are read at a 4096-token guard budget (`data/runs/<run>_b4096/`). Rules-only (`main_ablation_rules`) and the PI detector (`main_baseline_pi`) make no input-guard LLM calls and have no budget variant; their G2 output guard ran at 768 tokens, with 0.3% (rules-only) and 1.5% (PI detector) output-guard parse failures. The suffix is set in one place: [`gurma/eval/run_names.py`](../src/gurma/eval/run_names.py).

The 768-token originals (`data/runs/<run>/`) are kept only for the paired budget comparison.

| Report section | Question | Source |
|---|---|---|
| Main result (Tables 1–4, mechanism, cost) | Does the frozen hybrid defense work? | `main_b4096/6_metrics/metrics.json`, `main_b4096/7_ablation/pilot_gate_summary.json` |
| E1 Placement | Where must the guard sit? | `main_placement_b4096` |
| E2 Composition | Rules vs LLM vs hybrid; external baselines | `ablation_compare/`, `main_ablation_llm_b4096`, `main_ablation_rules`, `baseline_compare/` |
| E3 Guard capacity | Does guard size matter? | `e6_capacity_compare/`, `guard_size_compare/`, `main_e6_*_deepseek_b4096` (large guard without a reasoning trace) |
| E4 Distribution shift | Known vs unseen vs adaptive attacks | `main_b4096`, `main_transfer_b4096`, `main_adaptive_b4096`, `xfer_size_compare/` |
| E5 Transfer | Other dataset and target model | `main_squad_b4096`, `main_third_model_b4096` |
| E6 Guard budget and failure handling | 768 vs 4096; budget sweep; fail-open vs fail-closed; retry and recovery policies | `budget_compare/`, `budget_sweep/`, `failure_policy/`, `recovery_policy/` |
| Independence checks | Are attack generator, guard and judge different models? | `judge_agreement/`, `a2_generator/`, all `*_a2ds` runs (A2 regenerated by deepseek) |
| E7 CoT guard prompt | Does explicit reasoning help? Are decisions sensitive to cited evidence? | `cot_compare/`, `main_cot_*/8_faithfulness/` |

Some folder names predate the E1–E7 numbering: `e6_capacity_compare/` and the `main_e6_*` runs belong to E3, and `main_transfer` holds the E4 unseen-template run.

The gpt-oss (120B) cells in E3 and the 50-seed rows in E2 baselines are cut from the 100-seed main runs (`*_matched50_b4096`, `main_e6_*_gptoss_b4096`), not re-run.

## Regenerating

The comparison files must be rebuilt before the report if any run changed:

```bash
gurma ablation-report
gurma baseline-compare
gurma guard-size-compare
gurma capacity-compare
gurma xfer-size-compare
gurma budget-compare
gurma budget-sweep
gurma failure-policy
gurma recovery-policy
gurma cot-compare
gurma a2-generator-compare
gurma report
```

`gurma judge-agreement --judge ministral-14b` re-asks the P2 judge calls and needs the inference API.

[`scripts/post_queue.sh`](../scripts/post_queue.sh) runs the budget, CoT and report steps after a rerun queue finishes.

## Conventions

- **Recovery policies** (E6): F0 fail-open, F1 fail-closed, F2 retry then block, F3 retry then rules sanitize then block. A retry at budget R reuses the run at that budget on the same condition; no LLM calls. New runs can apply these policies for real with `guard_failure_policy` (`fail_open` | `fail_closed` | `retry_then_block` | `retry_then_sanitize`) and `guard_retry_max_tokens`; every reported run used `fail_open`.
- **Fail-closed** (E6): a counterfactual re-scoring of the 768 runs in which an unparseable guard output counts as a block (attack fails, answer wrong). No LLM calls.
- **Safety ASR**: mean attack success over A1 indirect injection, A3 policy-violating retrieval and A4 authority conflict. Lower is better.
- **PSR**: attack success on A2 context poisoning, reported separately as an integrity metric.
- **Acc**: task accuracy on attacked cases. **Benign Acc**: accuracy on clean cases.
- **G0 / G1 / G2**: no guard / input guard / input + output guard. Placement uses Q / C / O / CO instead.
- Brackets are 95% percentile bootstrap CIs (n=2000). Paired comparisons report Δ with a paired-bootstrap CI and an exact McNemar p.
- Counts are experimental conditions, not LLM API calls.
- The findings text and the paper-changes appendix in `main-e1-e7-results.md` are written by hand inside [`paper_report.py`](../src/gurma/eval/paper_report.py) (`FINDINGS`, `PAPER_CHANGES`). Update them there when numbers change; the tables update automatically.
